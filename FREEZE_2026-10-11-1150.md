## What changed
The live engine now fires the instant the trigger level is touched on the
currently-forming candle (intrabar), using the real-time price as the entry,
instead of the next completed candle's open. The fired trade is persisted
("frozen") so the stateless decision API serves a STABLE entry/stop/target for
the rest of the session — the alert exit-sweep compares each poll's entry to the
one it recorded, so a drifting live entry would raise spurious FLAT exits.

- `app/live/engine.py`
  - `_select_entry` (new, pure): historical next-open when a completed entry
    candle already exists; otherwise live intrabar entry (live price, fallback
    forming-candle close/open) with `entry_time = now`.
  - `_cpr_book_signal`: scans completed candles + the forming candle; entry via
    `_select_entry`; new params `live_price`/`now`.
  - `_freeze_trade` / `_frozen_trade` (new): persist/read the one-trade-day lock
    + `qualified_trades` row (status ACTIVE). `_consume_daily_lock` removed.
  - `evaluate`: passes live price/now; serves the frozen trade when present;
    freezes a freshly-fired live trade on the write path (never on dry_run).
- `scripts/tg_alerts.py`: on the first TRADE detection, POST
  `/api/<INST>/decision/claim` to freeze server-side, then alert using the
  frozen (stable) trade values. Added `api_post()`.
- `app/api/app.py`: claim docstring updated (repeats now serve the frozen trade).
- `frontend/signal-flow.html`: entry timing note -> intrabar (entry == signal
  instant); worked examples updated.
- `tests/test_intrabar_entry.py` (new): `_select_entry` (historical/intrabar) and
  `_freeze_trade`/`_frozen_trade` idempotency/stability.
