## 2. Signal-to-Paper-Trade Flow (Actual, Observed from Code)

There are **three distinct paths** in the production code. Only two are active.

### Path A — LiveEngine (ACTIVE, via gunicorn API)
```
app/live/engine.py:LiveEngine.evaluate()
  └── _hlc_book_signal()          # app/research/scalp_engine._scan_signals + _live_signal
        └── _freeze_trade()       # writes qualified_trades + daily_trade_locks
```
- **Writes to:** `qualified_trades` table, `daily_trade_locks` table
- **Does NOT write to:** `paper_trades` table
- **Triggered by:** `/api/decision/<instrument>` (gunicorn workers, always running)
- **Status:** ACTIVE — HLC IS the default live decision engine

### Path B — paper_scalp_live.py (NOT RUNNING)
```

  └── scalp_engine.today_signals()
        └── scalp_signal_store.record_signal()   # writes scalp_signals
              └── PaperTradeEngine().create_paper_trade()  # writes paper_trades
        └── PaperTradeEngine().monitor()         # exit monitoring
```
- **Writes to:** `scalp_signals` table, `paper_trades` table
- **Triggered by:** Nothing — script exists but is NOT running as a service or cron
- **Status:** NOT RUNNING (not in `ps` output, not in cron)

### Path C — tg_alerts.py --watch (ACTIVE, via cron)
```
scripts/tg_alerts.py:do_watch()
  └── GET /api/strategy/scalp       # calls scalp_engine.today_state()
        └── PaperTradeEngine().create_paper_trade()  # writes paper_trades
  └── do_watch() exit sweep         # PaperTradeEngine().monitor()
```
- **Writes to:** `paper_trades` table
- **Triggered by:** Cron `* 9-15 * * 1-5` (every minute during market hours)
- **Reconcile:** `tg_alerts.py --reconcile` runs at `10 9 * * 1-5`
- **Status:** ACTIVE via cron

**Finding:** HLC signals ARE generated by the live engine (`_hlc_book_signal` in `live/engine.py`) and persisted as `qualified_trades` + `daily_trade_locks`. However, paper trades in `paper_trades` are created only by separate scripts (`paper_scalp_live.py` not running, or `tg_alerts.py --watch` via cron). The live engine does NOT write to `paper_trades`.

## 3. End-to-End Trace

### Signal Detection → Decision API
```
market_candles_5m (completed 5m candles)
  ↓ (LiveEngine.evaluate, gunicorn worker)
app/live/engine.py → _hlc_book_signal()
  └── app/research/scalp_engine._scan_signals()     # 3-bar HLC alignment
        └── app/research/scalp_engine._live_signal() # entry/stop/target/risk
  └── app/live/engine.py → _freeze_trade()          # qual + daily lock
    └── qualified_trades + daily_trade_locks (DB write)
  └── API response: /api/decision/<instrument>      # JSON with trade object
```

### Paper Trade Creation (via tg_alerts cron)
```
cron: scripts/tg_alerts.py --watch (every min 9-15)
  └── GET /api/strategy/scalp?instrument=NIFTY
        └── scalp_engine.today_state()  # HLC signals from live engine
  └── PaperTradeEngine().create_paper_trade(qt, link_key=link)
        └── paper_trades (INSERT, deterministic trade_id from link_key)
  └── tg() Telegram message (sendMessage)
  └── build_alerts_page.py (regenerate frontend/alerts.html)
```

### Exit Monitoring (via tg_alerts --watch)
```
cron: scripts/tg_alerts.py --watch (every min)
  └── PaperTradeEngine().monitor(inst)
        └── market_snapshots table (latest price)
        └── UPDATE paper_trades SET exit_price, exit_reason, status='CLOSED'
```

## 8. Blocking Defects and Risks

### Defect 1 (HIGH): `paper_scalp_live.py` not running as a service
The dedicated live paper trading script exists but is not deployed as a systemd service or cron job. Without it, HLC signals generated by the live engine are only persisted as `qualified_trades` + `daily_trade_locks`, not as `paper_trades` via the dedicated script. Paper trades are only created via `tg_alerts.py --watch` cron, which is a secondary path.

### Defect 2 (HIGH): `market_snapshots` table is empty
The paper trade engine's `monitor()` method depends on `market_snapshots` for exit detection (stop/target hits). With 0 rows, open paper trades will never be exited via the monitor. The `tg_alerts.py --watch` exit sweep uses `closed_trade_by_id()` which also reads `paper_trades` directly (not snapshots), so it may still work for already-recorded exits, but real-time exit monitoring is broken.

### Defect 3 (MEDIUM): Mode A enforced instead of Mode C
The live engine's `_freeze_trade()` enforces ONE trade per day per instrument via `daily_trade_locks` UNIQUE constraint. This is Mode A behavior, not Mode C (one open position per instrument, resume after close). Mode C requires checking for open positions before allowing a new trade, which is not implemented in the live engine's freeze path.

### Defect 4 (MEDIUM): Dual paper-trade creation paths
Paper trades can be created by both `paper_scalp_live.py` (not running) and `tg_alerts.py --watch` (cron). Both use `PaperTradeEngine().create_paper_trade()` with deterministic `link_key`, so duplicates are prevented by PRIMARY KEY. However, the two paths use different signal sources (`today_signals()` vs `/api/strategy/scalp` API), which should return the same data but could diverge under load.

### Defect 5 (LOW): No holiday check in `paper_scalp_live.py`
`market_open_now()` only checks weekday (Mon-Fri) and time (09:15-15:30). It does not check NSE holidays. On a holiday, the script would attempt to create trades with no market data.

### Defect 6 (LOW): `qualified_trades` vs `paper_trades` split
The live engine writes to `qualified_trades` (via `_freeze_trade`), while paper trades are written to `paper_trades` (via `create_paper_trade`). These are separate tables with no foreign key relationship. Reconciliation requires the `scalp_reconcile.py` module or manual cross-referencing.

## 9. Minimal Implementation Plan (for Phase 2, pending approval)

If approved, the implementation should:

1. **Deploy `scripts/paper_scalp_live.py` as a systemd service** (or add to cron) so HLC signals are continuously converted to paper trades.
2. **Populate `market_snapshots` table** or modify `PaperTradeEngine.monitor()` to read from completed 5m candles instead of snapshots for exit detection.
3. **Implement Mode C position tracking** in the live engine's `_freeze_trade()` or in `paper_scalp_live.py`: check for existing open positions before creating a new trade, resume after position closes.
4. **Add holiday check** to `paper_scalp_live.py.market_open_now()`.
5. **Ensure `qualified_trades` → `paper_trades` reconciliation** is maintained, either via a unified write path or via `scalp_reconcile.py`.
6. **Run focused tests** on signal timing, position overlap, daily limits, exit ordering, session boundaries, and deterministic results before deployment.

## 12. Conclusion

**HLC is NOT yet production-ready for live paper trading in Mode C.** The signal detection engine (`scalp_engine.py`) and live decision engine (`live/engine.py`) correctly implement the HLC 3-bar rules and are deployed as the default decision engine. However:

1. `paper_scalp_live.py` is not running as a service.
2. `market_snapshots` is empty, breaking paper trade exit monitoring.
3. Mode A (1 trade/day) is enforced instead of Mode C (1 open position).
4. Paper trades are created via a secondary path (`tg_alerts.py --watch` cron), not the dedicated live paper script.

**Phase 1 is complete. Awaiting approval for Phase 2 implementation.**
